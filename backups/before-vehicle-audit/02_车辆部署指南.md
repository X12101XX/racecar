# v2 车辆部署指南

适用目标：已有 ROS2 Humble、Python 3.10+、numpy、OpenCV、colcon 的昇腾板。安装器不提供操作系统、CANN 或设备驱动，也不修改已有代码。算法走 CPU，不调用昇腾 NPU；因此不存在把 x86 NPU 目标文件误部署到 ARM 板的问题。当前交付为独立 Python ROS2 源码目标包，在目标板构建。

## 1. 已知事实与待核实项

历史来源：聊天「配置 ROS2 与 USB 双网络」（thread 01a143d4-5a8b-7570-baf0-c158bdfbb47e）的命令/输出多次实际使用 `/opt/ros/humble/setup.bash`。用户指定的本地运行记录及缓存源码也一致：

```text
原记录目录：/home/x12101x/Documents/Codex/2026-10-16/referenced-chatgpt-conversation-this-is-an
历史驱动副本：docs/evidence/historical_racecar_driver_node.cpp
SHA256: e4ac3620ee101e9fa9819c1a939e87eecc044e75fd112bae952d143a64fcfeb5
```

驱动订阅 `/car_cmd_vel`，其转换为：

```text
throttle_pwm = 1500 + 100 * linear.x
steer_pwm    = 1500 - 970 * angular.z
```

历史源码存在 100ms 定时器，指令超过 500ms 后发送中立 PWM。这里仅证明保存的源码有此逻辑，不能证明当前烧录/运行的二进制与它一致。需要核对并在车轮架空时验证。不要用旧教程中“angular.z 为车体角速度”的假设直接驱动本车。

本程序任务节点内部仍使用 m/s 与 rad/s；安全网关计算 `delta = atan(wheelbase * yaw_rate / v)` 并限舵角，再交给上述旧接口。零线速度时输出 `(0,0)`，不尝试原地转向。舵机单位、符号、非线性、油门死区和反向电调序列都必须实测；`legacy_steering` 是待标定的兼容接口，不是硬件证明。

## 2. 安装与只读验收

1. 保留小车现有启动流程，不修改 `~/racecar`、udev、服务、网络、CANN 或系统包。
2. 将 `crossfire-car-v2.run` 复制到小车，普通用户运行 `bash crossfire-car-v2.run`。它只创建新目录，拒绝覆盖已有目录，不会自动构建或运动。
3. 进入它打印的目录，运行 `bash tools/build_car.sh`。构建只落在本包的 `ros2_ws/build,install,log`。缺依赖则退出；需要依赖时应先评估现有镜像，安装器不会自行处理。
4. 编辑 `config/vehicle_profile.json` 中的只读话题映射。启动原有传感器，然后 `bash tools/run_car.sh A --preflight`。
5. `bash tools/run_car.sh A` 启动只读感知和规划。终端显示独立日志目录。该模式不创建任何速度发布者；不能据此判定电调/舵机适配完成。

在只读终端可额外核实：

```bash
printenv ROS_DISTRO
ros2 topic list -t
ros2 topic info /car_cmd_vel --verbose
ros2 topic info /teleop_cmd_vel --verbose
ros2 topic info /scan --verbose
ros2 topic echo /odom --once
ros2 topic echo /imu/data --once
```

这些命令只读；不要为了查看状态发布零速度到其他程序使用的话题。

本包进程设置 `ROS_LOCALHOST_ONLY=1`，只与同一块板通信，默认 domain 0。若原驱动使用其他域，在 profile 中填写相同 domain。不会调整现有驱动的 DDS 环境。

## 3. 首次上车必须完成的标定

| 项目 | 验收依据 | profile 确认项 |
|---|---|---|
| 底盘失联保护 | 架空验证控制发布者退出后，底盘在规定超时内中立；不能只看源码 | hardware_watchdog_confirmed |
| 转向/速度映射 | 正负号、舵机中立、舵角、前进/倒车、油门死区、限速；轴距与矩形包络实测 | steering_mapping_calibrated |
| 传感器坐标 | 激光扫描已转换到车体中心、正 x 前进/正 y 左；IMU 正 z 左转；里程计单位 m/s；固定安装位置 | sensor_frames_calibrated |
| 场地与起点 | 场地尺寸、起点朝向、据点/营地坐标和 1×1m 区域；车辆起步在配置起点 | field_and_start_measured |

赛题要求实车摄像头至少 720P；应在现有相机驱动中核实实际输出。仿真相机为减少本机渲染开销使用 320×240，这不能作为实车分辨率达标的证明。

本版传感器融合及网关假设 LaserScan 已在车体中心且前向角为 0，IMU 航向与场地坐标一致。它不会自动查 TF 或猜安装偏移。若驱动输出原始激光安装坐标，应在独立适配节点中正确转换后，将 profile 指到转换后的话题；在此之前保持确认项 false。角度偏移和位置偏移不能只改一个 TF 名称就视为完成。

根据实测更新 `body_length/body_width/wheelbase/max_steer/max_speed/reverse_limit`；同时调整独立包的 `config/field.json` 和 `route_a/b.json`。运行器会创建每次运行配置副本，将 profile 的车辆几何同步给任务规划器和安全网关。允许倒车前须确认 360°/后向有效测距以及电调反向行为，`allow_reverse` 初始 false。

旧 `calibrate_drive --confirm` 动作针对差速车，本版明确拒绝执行。不能用原地旋转标定阿克曼车。

## 4. 明确启用动作

完成标定、现场有人能物理急停，并由操作者处理现有控制器的控制权后，才执行：

```bash
bash tools/run_car.sh A --arm
# B 同理
```

运行器先只读自检，确认项缺失就退出，不创建底盘输出。启用后，只有网关可向 `/car_cmd_vel` 发布；任务节点仅发布 `/crossfire/desired_cmd`。网关发现同话题另一个发布者，或 `/teleop_cmd_vel` 存在发布者，会锁存停车而不杀死其他节点。该检查不能覆盖绕过 ROS 直接写串口的未知程序，故现场控制权仍需确认。

软件急停（已启用任务时，在同域、同板环境）：

```bash
ros2 topic pub --once /crossfire/estop std_msgs/msg/Bool '{data: true}'
```

急停为锁存，发送 false 不恢复。Ctrl+C 结束本次任务，再检查并重新启动。软件急停不能替代物理急停。进程、系统或供电完全失效时，最终停车取决于底盘已验证的保护逻辑。

## 5. 恢复

Ctrl+C 只结束此包创建的进程；不调用全局 pkill、不停原有服务、不取消其他任务。随后删除本次新建的目录即可卸载。`~/.local/state/crossfire/mission.lock` 仅是跨 release 的进程互斥锁；进程退出自动释放锁，不影响原有代码。所有任务结果保存在该 release 的 `runs/`。

结论边界：本机真实 Humble 闭环和故障注入可验证软件行为；尚未连接当前小车进行标定或运动，不能声称此包已完成真车验收或保证绝不会发生物理事故。默认锁定实车输出正是为了让未知接口不会直接驱动车辆。
