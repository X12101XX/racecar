# 现场配置与运动调参

电脑上运行 `bash tools/configure.sh`，浏览器打开 http://127.0.0.1:8765/ 。只需要 Python 标准库，不需要 ROS2。界面只编辑、校验、保存和导出，不启动小车或仿真。仅监听 127.0.0.1，没有外部 CDN/云服务依赖。

## 量什么、怎么填

左下角取 (0,0)，x 向右、y 向上，单位米。起点朝向单位度，0° 朝右、90° 朝上；必须与小车实际摆放、IMU 航向基准一致。

- 场地长宽是包围框。修改长宽不会自动缩放已填写的区域和障碍，避免覆盖实测坐标。
- 据点和营地各填中心 x/y 及长宽，可在俯视图拖动中心；不要求左右对称，也不要求恰好 1×1m。
- 雷区左右边界及三条封锁线 x 各自填写，不强制 4m 或 1.5m 等间距。标准赛题偏差会显示提示；几何不合法才阻止保存。
- 围栏轻微歪斜时点击“使用围栏四角”，拖动角点或输入四行 `x,y`，按顺/逆时针排序，组成不交叉的凸四边形。包围框应覆盖全部角点。只需测四个角；中间弯曲、断口或大幅不规则围栏未建模，可增加规划余量并现场核实。
- 场地雷达射线、碰撞检查、相机围栏与墙定位会使用这些角点，不是只改一张示意图。区域越界、车体或保护余量放不进起点、交叉围栏、过小终点区会被拒绝。
- 锥桶在图上拖动或表格中输入坐标、底面半径。删除需先选中障碍。勾选“已知”的锥桶会加入控制器先验地图；未勾选的只在仿真世界中存在，控制器需用雷达发现。不要为了测试成功把未知障碍全部勾成已知。

界面包含示例：`default`、`measured_example`（7.4×4.2m、非等距封锁线、略歪围栏）和 `aggressive_demo`。加载示例不会自动应用到真车。

## 保存、备份和搬到车上

保存名用英文、数字、短横线或下划线。源配置保存到 `profiles/名称.json`，旧版本保留在 `profiles/history/`；运行文件输出到 `profiles/generated/名称/`，不覆盖原 `config/`。每次运行还会保留配置副本和节点日志。

保存后界面显示完整仿真命令，例如：

```bash
bash tools/run_ros_sim.sh --profile measured_example --route A
# 或直接传入“导出源配置 JSON”得到的文件：
bash tools/run_ros_sim.sh --profile "/绝对路径/scene.json" --route B
```

`--profile` 会重新校验源 JSON，自动编译独立快照并选择 `configured` 场景，场地、锥桶、路线和运动参数均来自这份配置；不会误用默认锥桶。仿真过程中再修改界面，不会改变本次运行。保存后重新运行才会生效。结果默认写入新的带时间戳的 `output/配置名_路线_时间/`，终端会打印实际路径，内含 `video.mp4`、`final.png`、`summary.json` 和实际运行的 `config/`。

路径相对于执行命令时的当前目录，也支持绝对路径、空格和中文。保存名称从项目 `profiles/` 查找；文件应为源配置 JSON（或 ZIP 解压后的 `scene.json`），不要传运行目录中的单个 `field.json`。高级用法仍可传 `--scenario configured --config-dir /workspace/profiles/generated/名称`；`--profile` 不与这两个参数混用。`demo` 使用旧固定演示，`random` 使用随机布局。

点击“导出配置包 ZIP”，在车端解压到独立目录后：

```bash
bash tools/run_car.sh A --config-dir /绝对路径/导出配置目录
```

该命令仍默认只读。沿用原来的硬件确认流程，确认完成后才能加 `--arm`。车辆尺寸与已标定 profile 不一致时，实车动作会被拒绝，需要核对测量并更新硬件标定记录。ZIP 不会修改任何已标定限速、看门狗确认或底盘接口。

也可以导出/导入源 JSON，或使用命令行：

```bash
python3 tools/profile_config.py profiles/my_field.json --check
python3 tools/profile_config.py profiles/my_field.json --out profiles/generated/my_field
```

## 运动预设和细调

| 参数 | 保守 | 标准 | 激进 |
|---|---:|---:|---:|
| 直行速度 m/s | 0.28 | 0.40 | 0.65 |
| 弯道速度 m/s | 0.18 | 0.25 | 0.40 |
| 倒车速度 m/s | 0.12 | 0.20 | 0.25 |
| 加速度 m/s² | 0.35 | 0.60 | 1.00 |
| 跟踪前视距离 m | 0.18 | 0.22 | 0.30 |
| 规划额外余量 m | 0.13 | 0.10 | 0.12 |
| 换向停车等待 s | 0.50 | 0.35 | 0.25 |

这些数值实际用于阿克曼控制器：直行/弯道/倒车限速、加速斜坡、跟踪前视距离、规划车体膨胀、换向停车和到点误差均可调整。预设会覆盖运动值，场地不会被预设改变。激进预设在提高速度时保留 0.12m 规划余量，以吸收速度响应与跟踪误差；可单独调整，但不建议仅靠缩小余量提速。切换预设只影响下一次启动，不在行驶过程中热改。

可以不导出新场景，临时在仿真中覆盖运动预设：

```bash
bash tools/run_ros_sim.sh --route A --motion-preset aggressive
# 或实车只读：
bash tools/run_car.sh A --motion-preset conservative
```

**实车最终速度取“请求上限”和“已标定上限”的较小值。** 当前交付 profile 的前进上限 0.30m/s、倒车上限 0.15m/s。选择激进不会自动把它们提高；要让实车实际更快，须完成现场速度/转向/制动验证后修改 `vehicle_profile.json` 的 `max_speed/reverse_limit`。调整硬件参数必须与当前车辆标定一致，不靠打开确认开关代替验证。

“制动能力保守估计”用于预测制动距离，取较小值会更早停车；不允许大于原保护层保守值 0.6m/s²。独立网关采用相同估计，仍保留失联、急停和碰撞保护。提高速度不保证用时一定更短：转弯半径、障碍间隙、传感器时延会让它更频繁减速或停车。先在自己的场景中比较 `summary.json`、轨迹和碰撞记录，再选择参数。

## 本机验证边界

同一固定布局、同一 seed=1 的快速算法仿真，标准用时 46.95s、最终激进预设 39.33s，均零撞锥、零碰墙。该结果只适用于这一次场景，不代表所有布局提速；真实 ROS2、当前车辆与现场效果需分别看对应记录。

非标准示例在真实 ROS2 闭环中零碰撞完成，用时 46.039s；59项回归和4项原生ROS2检查通过。中间使用0.08m余量的旧激进试验曾在ROS2中触发保护并停车失败，最终预设已改为0.12m余量，相关失败记录保留，未算作成功。

最终激进预设的真实ROS2闭环：33.680s完成，零撞锥/碰墙，实测仿真线速度峰值约0.65m/s（output/config_aggressive_final_ros）。导出的独立实车包已在无设备的容器内构建并验证新参数，未标定的 --arm 仍被拒绝。数据摘要：output/config-validation.json。

新增直接传配置入口验证：`--profile measured_example --route A --seed 1` 完成真实 ROS2 闭环，任务计时 41.201s、据点等待3.000s、零撞锥/碰墙，运行快照与页面保存的源配置完全一致（包括非标准围栏、全部17个障碍、运动参数）。JSON 文件路径、含中文/空格/字面 shell 字符的文件名、参数冲突及非法配置均另做入口检查。此次运行不是对所有场地/随机种子的成功率保证。证据：`output/profile-entry-checks.json`。
