# 绿色安装、目录迁移与无 Docker 运行

车端默认使用原生 ROS2 Humble，复用已有 Python、NumPy 和 OpenCV；不需要 Docker、colcon、pip 或创建新的 ROS 工作空间。C++ 仅在安装时按开发板本机架构编译。安装不启动 ROS 节点、模型推理会话、摄像头、传感器驱动或底盘。

## 小车：放到自己指定的目录

推荐将绿色包 `release/crossfire-car-v2.tar.gz` 复制到车上。Linux 使用 tar.gz 可以保留脚本执行权限，无需自解压安装器。以普通用户在压缩包所在目录运行：

```bash
DEST="$HOME/my-crossfire-v2"  # 可更换；父目录需已存在，目标目录必须尚不存在
mkdir -m 700 -- "$DEST" &&
tar -xzf crossfire-car-v2.tar.gz --strip-components=1 --keep-old-files -C "$DEST" &&
cd -- "$DEST"
```

`mkdir` 不使用 `-p`，遇到已有文件、目录（即使为空）或链接会失败；`&&` 保证此时不继续解压，`--keep-old-files` 再次阻止覆盖文件。请保留整段命令中的 `&&`，不要直接向旧工作空间解压。解压不检查 ROS、不编译、不运行包内脚本；目录支持空格和中文，程序从自身位置找源码、模型和默认配置，不需要修改原来的安装路径。后续 `./crossfire install` 会检查包内 MANIFEST 中的源码哈希。

准备运行时，在包目录内执行：

```bash
./crossfire install             # 复用已有依赖，仅在本目录 .runtime/car/ 准备 C++
./crossfire doctor              # 只检查环境，不连接传感器、不创建节点
./crossfire run A --preflight   # 启动原有传感器后，进行只读自检
./crossfire run A               # 只读感知和规划；不创建速度发布者
```

B 路线将 A 改成 B。灰度线上赛默认不识别色卡。要识别色卡：

```bash
./crossfire run A --use-card --ai-backend fast_color
```

ONNX、NPU 是可选依赖，安装器不自动安装，协议和板端限制见 [视觉指南](07_NPU与GPU视觉加速指南.md)。依赖已经兼容时：

```bash
./crossfire run A --use-card --ai-backend onnx --ai-model models/card_classifier.onnx
```

这些命令仍为只读。只有完成 [实车适配与标定清单](06_实车适配与标定清单.md)，确认现场控制权后，由操作者明确加 `--arm` 才能产生底盘输出；本次没有连接实车，不能把软件安装验收当作实车验收。

非标准 ROS 安装位置或 Python 解释器：

```bash
./crossfire install --ros-setup /现有ROS/setup.bash --python /匹配的/python3
```

如果 CANN/ACLLite 需要额外的环境变量，可将已有 ROS 与 CANN 环境脚本组合为本目录中的私有 setup 脚本，再通过 `--ros-setup` 指定；只在本包子进程中加载，不修改全局 shell 配置。

程序会实际导入该解释器中的 rclpy 和消息类型核对兼容性，不凭 Python 版本号猜测。准备失败后，新目录保留，可修复依赖环境或选对已有解释器后再次执行：

```bash
./crossfire install --ros-setup /现有ROS/setup.bash --python /匹配的/python3
```

缺依赖时停止并报告缺项，不安装、卸载或升级软件。没有 C++ 编译器时明确报告 Python 回退。旧的 `bash tools/build_car.sh`、`bash tools/run_car.sh A` 保留兼容。

### 可选：自解压校验工具

`.run` 与 tar.gz 包含相同的源码目录，保留为需要解压前校验时的可选工具：

```bash
bash crossfire-car-v2.run --target "$HOME/my-crossfire-v2"
```

它先验证整个压缩内容和逐文件 SHA256，拒绝非法路径、归档链接及已有目标，然后只解压。省略 `--target` 时使用 `~/crossfire-releases/crossfire-时间/`。`--extract-only` 保留兼容，现在不加它也是只解压；显式添加 `--prepare` 才会额外准备本包运行环境，此时支持 `--ros-setup`、`--python`。

## 移动、升级与卸载

- **同一台车换目录：** 先结束本包任务，然后移动整个目录（包括隐藏的 `.runtime/`），再执行新位置的 `./crossfire doctor`。无需编辑配置中的项目根路径，也不需要重新编译；从其他工作目录使用该目录中 `crossfire` 的完整路径也可运行。
- **换开发板或 ROS/Python 环境：** 从原始绿色包重新解压到新目录，在新机器执行 `./crossfire install`；不会把电脑的 x86 动态库装到 ARM。非默认 ROS/Python 位置用上述参数指定，这只记录在本包私有运行信息中。
- **升级：** 解压到另一个新目录，旧版本和用户配置保留；按需复制自己的场地配置。安装器不原地覆盖升级。运行目录不属于本包、或其中含指向外部的符号链接/硬链接时，准备过程拒绝写入，不自动清理。
- **卸载：** 结束本包任务后，用文件管理器删除你自己指定的包目录即可；没有服务、系统包、环境变量或全局命令需要恢复。

不要将新版 tar.gz 直接解压进旧目录；按开头的命令创建新目录，保留旧版作为回退。

## 原有程序与环境如何保留

### install 与 doctor 分别做什么

| 命令 | 本包主动写入 | 执行内容 | 不执行的动作 |
| --- | --- | --- | --- |
| `./crossfire install` | 当前包 `.runtime/car/` 及其 `.runtime/` 父目录 | 检查已有 ROS/Python，使用已有编译器生成本机 C++ 库，保存环境信息；重复执行可更新本包生成文件 | 不安装/升级系统依赖，不修改 ROS、CANN、旧工作空间或 shell 配置，不启动 ROS 节点、模型或设备 |
| `./crossfire doctor` | 无主动写入 | 校验源码及私有库哈希，加载已有 ROS 环境并导入依赖，打印状态 | 不编译、不修复、不自动安装，不创建节点、速度发布者、控制锁或运行目录 |

`install` 中的“安装”指准备本包的私有运行文件，**不等于对系统执行软件安装**。两条命令设置的 `PYTHONPATH`、线程数等变量只作用于子进程，不会改变调用它们的终端或其他进程。普通用户执行即可，不要加 `sudo`。

**保证的边界：** 两者都会在子进程中执行所选的已有 ROS `setup.bash` 并导入已有 Python 依赖。普通用户运行不是文件系统沙箱；若自定义 setup、Python 启动钩子或编译器包装脚本本身包含包外写操作，本包不能阻止它。应使用可信的已有 ROS/Python/编译器；接入实车时先只读审阅自定义环境脚本。本次标准 Humble 环境的包外文件检查，以及整个包目录只读时的 `doctor` 验证，见 [环境审计记录](evidence/environment_audit_20261018.json)。

- 不写 `/opt/ros`、`/usr`、原 `~/racecar` 工作空间，不改 `.bashrc`、PATH 配置、udev、systemd、网络或 CANN，不调用 apt、pip、colcon。
- 按上述 tar 命令解压仅写新目录；可选 `.run` 还会创建缺失的父目录。均不会执行已有 ROS 环境脚本。后续显式准备的生成文件仅在其中的 `.runtime/car/`；不向系统安装 Python 包或注册同名 ROS 包。重复准备只允许本包标记过的私有运行目录。
- 运行时只在自己的子进程中加载选定 ROS 环境，并用自己的 Python 解释器直接启动自己源码中的节点，避免 `ros2 run` 找到旧工作空间里的同名程序。不会修改其他终端环境。
- 日志和实际使用的场地、硬件 profile 副本保存到本目录 `runs/时间/`。默认关闭车端 RViz 标记，限制本进程 NumPy/OpenMP 线程，减少非必要开销。
- 唯一跨版本运行文件是当前用户的 `~/.local/state/crossfire/mission.lock`，仅用于防止两个本包同时接管。安装不创建它；任务退出释放文件锁。不会停止原有服务、驱动或其他控制器。
- `Ctrl+C` 只终止本次创建的进程，任务先退出、网关最后退出。结束本包任务后删除该独立目录即可卸载；旧版本目录仍可直接运行，互不覆盖。

以上保护针对本包工具及本文给出的完整解压命令；使用其他解压工具时，应选择新的空目录并拒绝覆盖。运行时的跨版本互斥锁已单独列明，不属于安装写入。硬件单位、传感器坐标和物理制动仍需实车核验。

## 电脑：默认无 Docker 仿真

完整源码/仿真包中：

```bash
./crossfire sim --route A
./crossfire sim --route B --no-video
./crossfire sim --profile measured_example --route A
./crossfire sim --use-card --card-color red --planner-engine native
./crossfire sim --route A --motion-preset aggressive
```

本机需要已有 Python、NumPy、Pillow，OpenCV/SciPy 可选，生成 MP4 还需已有 ffmpeg。依赖缺失会报错，不自动修改系统；电脑可自行使用私有 venv。这个模式直接运行同一算法和自行车模型，**不含 ROS DDS 和独立网关进程**。每场保存独立配置快照和输出，不覆盖用户场地文件或旧结果。

本机仿真也保持传感器边界：`SimWorld` 生成物理真值，任务只通过 `RobotIO` 获取带噪声的雷达、IMU、里程计和相机样本；普通 `map.png`/`trajectory_estimated.csv` 是任务估计，`evaluation_truth.png`/`cones.json`/`trajectory.csv` 和碰撞/召回率只用于评分。默认不注入锥桶真值或先验。

若电脑已有原生 ROS2 Humble，可进一步执行完整 DDS 闭环：

```bash
./crossfire install
./crossfire ros-sim --route A
./crossfire ros-sim --use-card --card-color red
./crossfire ros-sim --fault estop
```

原生 ROS 仿真使用独立 DDS domain，并将模拟传感器、命令、状态和急停话题映射到每次运行的唯一前缀，不发布小车底盘话题。它不会自动安装 ROS。旧 Docker 仿真仅保留为可选测试环境，不再是默认入口。

默认自检也不调用 Docker，推荐统一入口：

```bash
./crossfire test --quick   # 单元测试 + Route A，快速迭代
./crossfire test           # 单元测试 + A/B/色卡
./crossfire test --ros     # 已有原生 ROS 时增加 DDS 和急停验证
./crossfire test --docker  # 旧容器测试，显式选择
```

也可以直接使用底层脚本 `bash tools/selfcheck.sh --quick` / `bash tools/selfcheck.sh --ros`。Web 配置界面的“本机测试”面板同样只调用本机算法仿真，不需要 ROS；它不启动 DDS、网关或底盘进程。

视频：`mpv output/latest/video.mp4`。使用 `--no-video` 时只生成指标、地图和轨迹，不会给出不存在的视频播放命令。
