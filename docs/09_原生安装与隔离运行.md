# 无 Docker 安装与运行

车端默认使用原生 ROS2 Humble，复用已有 Python、NumPy 和 OpenCV；不需要 Docker、colcon、pip 或创建新的 ROS 工作空间。C++ 仅在安装时按开发板本机架构编译。安装不启动 ROS 节点、模型推理会话、摄像头、传感器驱动或底盘。

## 小车：一条命令安装

将 `release/crossfire-car-v2.run` 复制到车上，以普通用户运行：

```bash
bash crossfire-car-v2.run
```

它先检查压缩包与每个文件的校验值，再创建全新目录（默认 `~/crossfire-releases/crossfire-时间/`），检查已有 ROS/Python 依赖并准备 C++ 库。**遇到已有目标目录会拒绝覆盖；缺依赖时会停止，不会安装、卸载或升级系统软件。** 缺少编译器时明确报告 Python 回退，不把它当成 C++ 已启用。

进入打印的目录：

```bash
./crossfire doctor              # 只检查环境，不连接传感器、不创建节点
./crossfire run A --preflight   # 启动原有传感器后，进行只读自检
./crossfire run A               # 只读感知和规划；不创建速度发布者
```

B 路线将 A 改成 B。灰度线上赛默认不识别色卡。要识别色卡：

```bash
./crossfire run A --use-card --ai-backend fast_color
```

ONNX、NPU 是可选依赖，安装器不自动安装，协议和板端限制见 [视觉指南](07_NPU与GPU视觉加速指南.md)。依赖已经兼容时：

```bash
./crossfire run A --use-card --ai-backend onnx --ai-model models/card_classifier.onnx
```

这些命令仍为只读。只有完成 [实车适配与标定清单](06_实车适配与标定清单.md)，确认现场控制权后，由操作者明确加 `--arm` 才能产生底盘输出；本次没有连接实车，不能把软件安装验收当作实车验收。

非标准 ROS 安装位置或 Python 解释器：

```bash
bash crossfire-car-v2.run --ros-setup /现有ROS/setup.bash --python /匹配的/python3
```

如果 CANN/ACLLite 需要额外的环境变量，可将已有 ROS 与 CANN 环境脚本组合为本目录中的私有 setup 脚本，再通过 `--ros-setup` 指定；只在本包子进程中加载，不修改全局 shell 配置。

程序会实际导入该解释器中的 rclpy 和消息类型核对兼容性，不凭 Python 版本号猜测。准备失败后，新目录保留，可修复依赖环境或选对已有解释器后再次执行：

```bash
./crossfire install --ros-setup /现有ROS/setup.bash --python /匹配的/python3
```

想先在电脑上查看源码而不准备 ROS：`bash crossfire-car-v2.run --extract-only`。旧的 `bash tools/build_car.sh`、`bash tools/run_car.sh A` 保留兼容，但已转到同一个原生入口。

## 原有程序与环境如何保留

- 不写 `/opt/ros`、`/usr`、原 `~/racecar` 工作空间，不改 `.bashrc`、PATH 配置、udev、systemd、网络或 CANN，不调用 apt、pip、colcon。
- 解压仅写新建的私有目录。安装产物为其中的 `.runtime/car/`，不向系统安装 Python 包或注册同名 ROS 包。
- 运行时只在自己的子进程中加载选定 ROS 环境，并用自己的 Python 解释器直接启动自己源码中的节点，避免 `ros2 run` 找到旧工作空间里的同名程序。不会修改其他终端环境。
- 日志和实际使用的场地、硬件 profile 副本保存到本目录 `runs/时间/`。默认关闭车端 RViz 标记，限制本进程 NumPy/OpenMP 线程，减少非必要开销。
- 唯一跨版本运行文件是当前用户的 `~/.local/state/crossfire/mission.lock`，仅用于防止两个本包同时接管。安装不创建它；任务退出释放文件锁。不会停止原有服务、驱动或其他控制器。
- `Ctrl+C` 只终止本次创建的进程，任务先退出、网关最后退出。结束本包任务后删除该独立目录即可卸载；旧版本目录仍可直接运行，互不覆盖。

这些保证针对安装文件操作和本包启动行为；硬件单位、传感器坐标和物理制动仍需实车核验。

## 电脑：默认无 Docker 仿真

完整源码/仿真包中：

```bash
./crossfire sim --route A
./crossfire sim --route B --no-video
./crossfire sim --profile measured_example --route A
./crossfire sim --use-card --card-color red --planner-engine native
./crossfire sim --route A --motion-preset aggressive
```

本机需要已有 Python、NumPy、Pillow，OpenCV/SciPy 可选，生成 MP4 还需已有 ffmpeg。依赖缺失会报错，不自动修改系统；电脑可自行使用私有 venv。这个模式直接运行同一算法和自行车模型，**不含 ROS DDS 和独立网关进程**。每场保存独立配置快照和输出，不覆盖用户场地文件或旧结果。

若电脑已有原生 ROS2 Humble，可进一步执行完整 DDS 闭环：

```bash
./crossfire install
./crossfire ros-sim --route A
./crossfire ros-sim --use-card --card-color red
./crossfire ros-sim --fault estop
```

原生 ROS 仿真使用独立 DDS domain，并将模拟传感器、命令、状态和急停话题映射到每次运行的唯一前缀，不发布小车底盘话题。它不会自动安装 ROS。旧 Docker 仿真仅保留为可选测试环境，不再是默认入口。

默认自检也不调用 Docker，推荐统一入口：

```bash
./crossfire test --quick   # 单元测试 + Route A，快速迭代
./crossfire test           # 单元测试 + A/B/色卡
./crossfire test --ros     # 已有原生 ROS 时增加 DDS 和急停验证
./crossfire test --docker  # 旧容器测试，显式选择
```

也可以直接使用底层脚本 `bash tools/selfcheck.sh --quick` / `bash tools/selfcheck.sh --ros`。Web 配置界面的“本机测试”面板同样只调用本机算法仿真，不需要 ROS；它不启动 DDS、网关或底盘进程。

视频：`mpv output/latest/video.mp4`。使用 `--no-video` 时只生成指标、地图和轨迹，不会给出不存在的视频播放命令。

## 验证记录

结果已记录在 [`docs/evidence/native_install_validation.json`](evidence/native_install_validation.json)：包括拒绝覆盖、损坏包/非法路径拒绝、依赖缺失不修改系统、两份并存安装、原生节点来源、只读发布者检查、本机无 Docker 仿真与兼容 ROS 环境中的原生 DDS 闭环。Docker 不属于新安装器或车端运行依赖；本机没有系统 ROS，完整 Humble 兼容性检查使用已有隔离测试环境。


本次验收：本机默认自检 98 项（97 通过，1 项因没有 ONNX Runtime 跳过）；已有 Humble/ONNX 测试环境中 98 项全部通过，另有 4 项真实 ROS 消息契约通过。原生 DDS 的固定 A 路线、红色色卡选择 B 路线均完赛且无碰撞，急停测试保持零输出。当前实测场地的本机仿真也已生成完整可解码视频。测试架构为 x86_64；ARM64 板端运行、NPU 及实际制动仍待上车验收。

2026-10-17 后续本机工具补充：默认自检现为 104 项（103 通过，1 项可选 ONNX 跳过），并新增 `./crossfire test --quick` 与 Web 页面内隔离仿真入口。这是本机工具与模拟器侧的新验证；上述 Humble/ROS/实车历史结论没有因本次界面或测试入口修改而重新执行。
