# v2 无颜色方案

比赛地图来自用户提供的赛题 PDF 第 2 页。根据用户后续澄清，线上赛全部物料无颜色，所以取消色卡识别和地贴确认。路线是参数，障碍统一处理；地图坐标的 A/B 是逻辑区域名称，不是颜色观测。

定位用里程计线速度、IMU 角速度/已对齐的航向与矩形围栏观测。墙面端点先旋转到场地坐标，再按已知边界位置修正，避免阿克曼转弯后把车体轴误认为场地轴。定位完全依赖已知起点和准确传感器坐标；尚未提供通用 SLAM/TF 安装自标定。

激光雷达射线做聚类与圆拟合，跨帧关联得到障碍地图。连续的长点簇（密集/重叠锥桶或低墙）无法按单圆拟合时，会沿点簇中心线采样成障碍链，避免“雷达看到了但规划地图为空”。没有从仿真直接把障碍真值注入控制器；演示默认无先验。完整相机图像仍通过 ROS2 发布并记录，任务在无颜色模式中不使用其颜色信息。障碍物颜色标签不会改变本版规划代价。

Hybrid A* 的状态为连续 `(x,y,yaw)`、离散索引与前进/倒车方向。每条扩展使用自行车曲率上限 `tan(max_steer)/wheelbase`；不存在零半径转向边。前后向展开均检查整段矩形车体扫掠，搜索使用绕障的二维代价到终点启发式，优先前进、惩罚换挡和倒车。搜索有时间和节点上限，失败停车；不代表对任意未知随机场地完备。

跟踪按同方向连续段进行，换向处先停车；纯跟踪输出 SI 线速度与角速度，并预测制动距离内车体扫掠。规划留出比保护层更宽的余量，避免跟踪误差和地图噪声把起点带入膨胀障碍。若当前位姿仍与融合地图重叠，先用短距、后向净空和扫掠检查通过的倒车弧尝试脱困，再重新规划；连续失败才停车。ROS 运行时搜索在后台线程执行，避免阻塞传感器和控制回调。

独立网关再次检查指令/传感器新鲜度、数据有效性、有效方向覆盖、限速、制动扫掠、竞争发布者和急停。它使用独立进程的墙钟；任务退出后仍可发送零指令。网关退出后的停车依赖底盘自己的已验证超时机制，单个应用无法对整条物理链路作绝对保证。

任务状态：初始化 → 显示指定路线 → 静止收集多帧雷达建立初始锥桶地图（默认约 2 秒 / 至少 5 帧） → 据点中心附近 → 实测速度稳定后等待至少 3 秒 → 规划穿过雷区至营地 → 停车 → DONE。碰撞统一失败；不按颜色区分罚时。官方计时以裁判/现场实测为准，软件内部用时仅用于仿真和调参。

旧版差速/彩色视觉方案和旧统计见修改前源码快照；v2 不使用其旧成功率作为验证结论。
