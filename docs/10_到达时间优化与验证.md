# 固定速度上限下的到达时间优化

日期：2026-10-18。基线为 `80a87eb`。本次目标是减少计算等待和不必要的弯曲跟踪，不提高车辆直行、弯道、倒车速度、加减速上限，不缩短建图等待、据点停驻或换挡等待，不放宽到点容差。

## 已采用的改动

1. **及时读取后台结果**：正在规划时不再受 0.6 秒重试间隔约束；结果完成后可在下一控制周期接收。0.6 秒间隔仍用于无任务正在运行时的失败重试。
2. **完整的后台重试**：规划余量的多次尝试都在同一工作线程运行，避免原生 ROS 控制回调同步执行后续搜索。结果明确返回所用余量，修复旧异步成功分支访问空 `plan_world` 的问题。
3. **利用必须静止的时间预取路径**：在建图等待和已确认停稳的据点等待即将结束时预取下一段。等待条件不变，预取本身不产生动作。使用结果前核对目标、起始位置/航向和当前融合地图；过期结果丢弃重算。
4. **以预计通行时间选择尾段圆弧**：越过第二道封锁线、当前及后续路径不涉及换挡时，尝试一条到目标的前进单轨圆弧。它必须满足最大转角、场地边界、完整车体扫掠和至少 0.13m 的规划余量，且预计比当前路径快 0.3 秒以上，才能替换路径。不能通过时继续使用原路径。实际输出仍经过原速度限制、制动扫掠和原始雷达保护。

算法只使用任务已融合的传感器地图与已配置的目标区域；不读取仿真锥桶真值或真实位姿来选路。C++ Hybrid A* 的搜索实现、ABI 和原有执行保护余量未改动。

## 对比结果

完整记录：[到达时间优化证据](evidence/arrival_optimization_20261018.json)。

矩阵共 130 个案例：A/B 各 60 个随机种子，演示 A/B、当前保存的三份场地 A/B，以及两组初始路线与色卡相反的测试。随机种子 40–59 未参与前期候选筛选。基线与候选使用独立冻结源码、相同输入配置、相同运动参数与原生规划库；比较器检查输入摘要和速度配置，不能以提高限速取得通过。

| 指标 | 基线 | 本次 |
| --- | --- | --- |
| 完赛数 | 108/130 | 108/130 |
| 新增失败 | — | 0 |

共同完赛案例平均全流程缩短约 **3.0%**，主要来自路径曲率与跟踪速度利用率改善，平均路长变化较小。单个案例最多减少 3.80 秒；也存在约 0.05 秒的轻微变慢，不能声称每个场景都会更快。22 个原有未完赛案例仍未解决，不将本次结果描述为任意场地必定完赛。异步预取对 ROS 等待的收益没有混入同步算法矩阵，需分别看 ROS 记录。

前期还试过更低启发式权重、更多转向分支、精确目标连接、连续投影和重规划速度衔接等候选。部分候选更快，却增加了窄通道失败；这些变化未进入最终运行代码。

## 验证范围

- 本机 128 项单元测试：127 项通过，1 项因没有可选 ONNX 运行库而跳过。新增测试覆盖异步结果消费、余量重试、旧结果丢弃、地图快照、静止预取、圆弧碰撞拒绝及比较器不能隐藏限速变化/新增失败。
- 已有 Humble 隔离环境中以原生入口启动，固定 A 路线和红色色卡选择 B 路线均完赛、全车进入对应营地、据点停稳至少3秒，锥桶与围栏接触为0。
- 同一原生 ROS 流程注入急停和雷达断流，均保持零输出。它们是模拟世界的故障验证，不代表实车的停车距离或硬件急停已验收。
- ROS 测试使用真实 DDS 和直接 Python 节点入口；目标流程禁止调用 Docker、colcon、`ros2 run`、pip 和 apt。本机没有原生 ROS，因此已有容器只作外部兼容测试夹具，交付运行不新增 Docker 依赖。
- ROS 的两次完赛用于验证接线、线程与保护行为。其消息调度和噪声采样不等于同步矩阵，不能用不同模式的用时作前后加速比。
- ARM64 开发板时延、物理运动、制动和昇腾 NPU 没有在本次验证。

## 在电脑完整源码或仿真包中复现

```bash
./crossfire test
./crossfire sim --profile measured_example --route A --planner-engine native

# 固定速度上限的批量比较；每个结果目录必须是新目录
bash tools/build_native.sh .runtime/arrival/libhybrid_astar.so
python3 tools/benchmark_arrival.py \
  --native-library .runtime/arrival/libhybrid_astar.so \
  --outdir output/arrival-current --seeds 60 \
  --profile my_field --profile aggressive_demo --profile measured_example --cards
```

基线需要保存为独立源码快照，包含其 `racelib/`、`sim/`、`config/`、所测 `profiles/` 和 `tools/profile_config.py`，并为该源码编译独立的 C++ 库。以 `--source-root /基线源码`、`--native-library /基线库.so` 运行同一工具。不要在用户正在编辑的工作区切换分支或恢复文件来做对比。

候选运行时可加 `--compare output/基线结果/matrix.json`。比较器的 `passed` 同时要求案例集合、输入与运动上限一致、没有新增失败/碰撞，且共同完赛案例的平均全流程时间改善。它不证明任意场地的可靠性，也不包含实车验收。

轻量实车包不附带整套批量仿真工具；使用电脑完整源码或完整仿真包执行上述命令。车端继续按 [原生安装指南](09_原生安装与隔离运行.md) 和 [实车标定清单](06_实车适配与标定清单.md) 执行。
