## 环境及隔离

宿主 CachyOS / x86_64；已有 Docker 29.9.0。基于官方 `ros:humble-ros-base` 镜像摘要 `sha256:566b87e6dfc48392189a9c32e594e84060fa9948de93b04e536f39475a1f6963` 构建 `crossfire-sim:humble-v2`。

Ubuntu/ROS 依赖只装在该镜像中。宿主未安装 ROS2 系统包，未改 shell、网络、udev 或小车。仿真运行使用 `--network none`、只读根文件系统、普通 UID、`--cap-drop ALL`、`no-new-privileges`，不挂载串口/USB/显卡，不使用 host 网络。只挂载项目源码为只读，允许写入 `.runtime` 构建目录与 `output`。修改前源码快照已保存，SHA256 为 `3767f9a3cdcd2f590117b1a89a10cc3d39b3c5f75a24d2983aea5e651a41699f`。

## 验证方法

1. 单元测试在镜像内的 Python 3.10、numpy 1.21 系列依赖上运行。覆盖几何、颜色旧模块兼容性、规划/跟踪流程、消息契约、无发布者的只读行为、舵机转换、车体扫掠、转弯后的墙定位和合规场地生成。
2. `tests/ros_native_contract.py` 使用真实 rclpy 和生成的 ROS 消息，独立验证默认不创建 `/car_cmd_vel`、`/cmd_vel` 或私有速度发布者，拒绝过期/无效数据，支持有行填充的图像。桩件测试与真实 ROS 测试明确分开。
3. `sim/ros_demo.py` 启动世界、任务节点和独立网关；通过真实 DDS 交换 LaserScan/IMU/Odometry/Image 和速度。控制器看不到世界真值。合规固定布局含 12 个封锁锥与 5 个其他障碍，全部灰色。
4. 仿真世界独立核实到达真实营地区域、矩形车体与锥桶/围栏碰撞。不能仅以控制器宣称 DONE 判断成功。
5. 行驶时主动注入任务 SIGKILL、雷达断流、软件急停、竞争输出发布者；同时检查首次零指令时间、随后持续归零、实际仿真速度衰减至停止。

最终数据见本文末尾自动汇总和 `output/` 中逐项原始日志/JSON。旧版差速/颜色测试以及中间调试目录中的成功率不适用于本交付。

## 限制

这是自行车运动学与传感器射线仿真，不是 Gazebo/真实轮胎物理模型。现场光照、轮胎打滑、舵机响应、油门死区、后向覆盖、传感器安装坐标和当前底盘失联保护尚未在当前车辆验收。默认 `vehicle_profile.json` 的动作确认项均为 false，因此交付包安装及默认运行不会发车。

随机布局只约束单条封锁线的间距及锥桶数量，不保证整个未知场地都存在满足阿克曼车辆几何和余量的路径。样本中任何安全停车/搜索失败均保留并计为失败；不能以少量样本宣称任意场地必定完赛。

故障停车计时是应用层首次零指令的实测延迟，后续机械制动受速度、地面和底盘影响，不能把 0.30/0.50 秒误解为任何真车的绝对停车时间。硬断电、系统/网关同时崩溃、未知进程绕过 ROS 直写串口等风险，须依靠已验证的底盘看门狗和现场物理急停。

## 前摄朝向与行进策略修正

用户当前布局的旧版本路线 A 实际前进1.652m、倒车6.300m，导致前置镜头与移动方向长期相反。现改为先搜索全程前进路径，失败后才允许每次规划最多0.66m倒车的备选。对应 ROS2 A 验证前进7.886m、倒车0.571m，任务计时35.380s，停稳等待3.000s，零撞锥/碰墙。短距倒车集中于据点后的机动，镜头始终固定朝车头。

相机俯仰矩阵符号同时修正，使相机到地面的投影与 CameraModel.ground_distance 一致。新增四个车头方向的左右像素、后方不可见、地面距离反投影、前进路径偏好与倒车累计距离上限检查；包含原回归共64项全部通过，日志 output/forward-camera-unit.log。视频现在标注前摄视锥、车头橙色箭头、移动青色箭头和实际挡向；summary.json 新增实际前进/倒车距离。完整记录见 output/forward-camera-validation.json。
