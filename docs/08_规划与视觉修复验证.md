# 规划、视觉与结果文件修复记录

日期：2026-10-17；审查起点为 Git `21857b7`。这是本机软件与 ROS2 仿真验证，不代表实车已经标定或完赛。最终实测表见文末，机器可读证据为 [revision_validation.json](evidence/revision_validation.json)。

## 发现与修复

1. **第一帧雷达地图坐标错误**：任务在 INIT 状态处理函数设置起点前先接收雷达，第一帧按 `(0,0,0)` 写地图。现在构造任务时先设置配置中的起始位姿，再接收传感器，避免错位障碍在地图中残留。回归测试使用非零起点核对首次观测的世界坐标。
2. **搜索与执行保护不一致**：旧规划将余量逐级降低到 0，但执行层仍按车体保护范围拒绝通行，形成“规划成功—停车—重规划”循环。现在最低余量为执行保护的 0.06 m；弯道先按同一矩形扫掠和制动距离检查减速，无法安全执行才停车重规划；异步结果接收时重新核对当前地图。没有修改安全网关的超时、急停与扫掠门限。
3. **C++ 搜索正确性**：原固定状态表超过约 10.8×6.3 m 会发生索引别名；节点容器扩容可能使当前节点引用失效；围栏只支持一个绕向；超时检查可能跳过；结果缓冲区不足时截断仍报成功。现使用按搜索状态增长的哈希表、拷贝当前节点、支持两种围栏绕向、按展开次数检查时间、拒绝截断路径。几何和积分内部改用 double，保留 C ABI；校验 ABI 版本，避免载入旧库。合法搜索失败不再无声重复执行整套 Python 搜索并超出原时间预算。
4. **视觉“已加载但不推理”**：原 ONNX/NPU 检测函数为空实现。现分别调用 ONNX Runtime 会话和 ACLLite 执行；显式后端缺模型/依赖直接失败，auto 回退会报告原因。修复首次色卡未经两帧确认就发车、跨空帧历史确认和 HSV 兜底绕过确认的问题。色卡超时停车；灰度模式不加载模型。相机几何按实际输入图像尺寸缩放。
5. **随机模型与不准确文档**：移除未训练的随机 CNN 导出，改为可复现 RGB 阈值 ONNX 图并附类型说明。它不是 YOLO，不能代替现场训练模型验收。撤销旧文档中无实测证据的板端性能、准确率、零抖动、零拷贝和任意场地必达承诺。
6. **视频覆盖和结果混淆**：所有默认仿真均使用独立时间戳目录；拒绝覆盖既有输出。ffmpeg 成功退出后才将 `video.partial.mp4` 改名为 `video.mp4`，完成标记写入后更新 latest。半成品不会取代最近完成的结果。同一项目的构建与运行加锁，防止并发改写共享 ROS install。
7. **部署架构隔离**：发布包排除电脑的 `.so`。容器/目标板在自己的环境编译；实车仅在私有解压目录构建。安装器拒绝 root、拒绝覆盖，默认硬件确认项仍为 false，没有安装系统包或修改驱动。

## 如何复测

在项目根目录运行：

```bash
# 在线赛默认仍是所有物料无颜色、手动选路
bash tools/run_ros_sim.sh --profile measured_example --route A
bash tools/run_ros_sim.sh --route B

# 不需要模型的 CPU 色卡模式
bash tools/run_ros_sim.sh --use-card --route A --ai-backend fast_color

# 可选依赖只安装到独立镜像；真实 ONNX 推理
bash tools/prepare_vision.sh
CROSSFIRE_SIM_IMAGE=crossfire-sim:vision-v2 bash tools/run_ros_sim.sh \
  --use-card --ai-backend onnx --ai-model /workspace/models/card_classifier.onnx

# 一键回归；完整的 ONNX/场地/激进预设矩阵另行运行
bash tools/selfcheck.sh
CROSSFIRE_SIM_IMAGE=crossfire-sim:vision-v2 python3 tools/validate_simulations.py

mpv output/latest/video.mp4
cat output/latest/summary.json
```

仅传 `--ai-backend onnx` 不会凭空生成或训练模型；旧命令在缺模型时会明确报错，需按示例提供模型与运行库。模型协议与昇腾待验证事项见 [07](07_NPU与GPU视觉加速指南.md)。实车尺寸、参考点、底盘接口、转向、制动和后向覆盖仍按 [06](06_实车适配与标定清单.md) 逐项核实。

## 验证边界与中间失败

初轮八场中，标准场地七场完赛，但当时用户实测配置一次在斜向窄缝附近失败；同配置重复又完赛。该中间失败保留在 `output/validation_20261017-174005-575437/measured_A`，不能按成功样本计算。进一步检查发现首帧坐标初始化问题后重新执行最终完整矩阵。

视频解码验证只对验证子进程移除 `LD_LIBRARY_PATH`，避免仓颉运行时中的 libpcre2 警告被误当成视频损坏；没有修改用户 shell 或系统库。

独立看门狗是 ROS 应用进程，不是硬件看门狗的替代；底盘自身失联保护和物理急停需实车验收。仿真无 USB/串口/GPU 设备映射，也没有实车连接。未知随机场地不保证存在满足阿克曼约束的通路。ROS 闭环按墙钟推进，DDS 调度和后台规划存在异步时序；固定 seed 不保证轨迹和耗时逐次完全相同，上表是有限样本验证。
